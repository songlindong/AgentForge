# ADR-003：Kafka 投递、顺序与幂等

状态：Proposed  
日期：2026-07-26

## 背景

APP/H5 消息、文档处理和 Agent 事件需要异步解耦。金融客服不能因重复投递产生重复回复或重复业务副作用。

## 决策

- Kafka 使用至少一次投递语义。
- 消费者通过业务幂等键、状态机和数据库/Redis 条件写保证重复安全。
- 同一 `conversation_id` 作为用户消息分区键，保证会话内有序。
- 文档事件使用 `document_id`，Agent 事件使用 `run_id`，审计事件至少携带 `tenant_id`。
- 临时错误指数退避，超过次数进入死信队列。
- 手工重放必须重新执行权限、版本和幂等检查。

## 不承诺

Kafka Partition 内有序不等于所有会话全局有序。不同会话允许并行处理。

## 后果

每个消费者需要保存处理状态、attempt、事件版本和失败原因；第 3 步定义具体 AsyncAPI 契约。
