# AgentForge 产品愿景与范围

状态：第 1 步产品规格基线，待确认  
版本：0.2.0  
更新日期：2026-07-25

## 1. 一句话愿景

为金融贷款机构提供一套面向 APP/H5 双渠道、回答可追溯、业务操作受控、Agent 可编排、能力可扩展并可在生产环境持续运营的企业级 AI 智能客服系统。

## 2. 要解决的问题

传统金融客服链路存在以下问题：

- 产品、政策、合同和业务流程分散，人工查询慢且口径不一致。
- 普通关键词检索难以处理金融术语、数字条款、长合同和同义表达。
- 扫描合同、产品图片和复杂表格无法直接转成可靠、可定位、可引用的知识。
- 大模型可能编造利率、额度、审批结果或合同结论，无法直接用于金融客服。
- 实时数据来自多个业务系统，接口权限、失败重试和审计缺少统一治理。
- APP 与 H5 容易形成两套接入和会话逻辑，维护成本高。
- Agent、工具和流程如果缺少状态、预算、权限和回放机制，难以稳定运行。
- 系统上线后缺少效果评测、安全隔离、容量验证、监控告警和回滚证据。

AgentForge 通过统一渠道接入、金融 Knowledge Base、分层 Memory、Agent Runtime、Agent 编排、Skill Registry、MCP、安全沙箱、企业级 LLM Gateway 和可观测性体系解决这些问题。

## 3. 产品目标

### 3.1 客户服务目标

- 用户可以通过 H5 和 APP 获得一致的金融咨询服务。
- 产品、政策和合同回答必须给出可追溯来源。
- 利率、额度、征信和审批状态等动态信息必须通过授权业务接口获取。
- 低置信度、资料冲突、高风险或用户主动要求的会话可以转人工。
- 多轮会话保持必要上下文，同时允许删除、过期和审计。

### 3.2 运营与合规目标

- 运营人员可以管理金融文档、产品资料、Agent、Skill 和发布版本。
- 合规人员可以检查回答依据、工具调用、权限决策和敏感操作。
- 所有高风险操作都必须具备身份、权限、确认和审计记录。
- 不同租户的数据、Memory、Knowledge Base、Skill 和配置必须隔离。

### 3.3 平台工程目标

以下五项为永久核心目标：

1. Agent Runtime 内核、Agent 编排与 Skill 体系。
2. 安全沙箱与隔离环境。
3. 企业级 LLM Gateway。
4. 高效 Memory 与 Multimodal Knowledge Base。
5. 高并发 LLM Gateway 与百万级 RAG 优化。

每项能力必须具备规格、实现、Harness 验证、上线门禁和生产监控，任一目标未通过不得标记为正式上线完成。

## 4. 用户与系统角色

| 角色 | 核心职责 |
|---|---|
| 贷款咨询用户 | 通过 APP/H5 咨询产品、政策、合同、还款及申请状态 |
| 人工客服 | 接管转人工会话，查看必要上下文并回复用户 |
| 知识运营人员 | 上传、审核、发布、回滚金融文档和产品资料 |
| Agent/Skill 运营人员 | 配置 Agent、Skill、模型策略、权限和灰度范围 |
| 合规与审计人员 | 审查回答依据、拒答、工具调用、数据访问和审计事件 |
| 租户管理员 | 管理本租户用户、角色、知识库、渠道和配额 |
| 平台管理员 | 管理模型、全局策略、容量、租户和平台配置 |
| 系统运维人员 | 负责部署、监控、告警、备份、恢复和事故处置 |
| 外部业务系统 | 提供产品、利率、额度、征信和审批状态等授权动态数据 |

详细用户故事见 `user-stories.md`。

## 5. 渠道范围

只建设两个客户渠道：

1. H5：首先打通完整业务闭环。
2. APP：在 H5 闭环验收后，通过统一渠道契约接入。

APP 和 H5 共用身份映射、会话、消息、Agent、RAG、工具调用和审计链路。不扩展其他客户渠道。

## 6. 业务场景范围

### 6.1 P0：首发必须具备

- 产品与申请条件咨询
- 金融政策和合规问答
- 合同条款解读
- 还款计划试算
- 产品检索与基础推荐
- 利率、额度和审批状态的模拟或授权查询
- 多轮会话与摘要
- 回答引用和来源查看
- 拒答、风险提示和转人工
- 知识库运营、版本发布和回滚
- PDF、扫描 PDF、PNG/JPEG 的安全上传、OCR、版面分析、表格提取和页级/区域级引用
- Agent/Skill 注册、配置、权限、灰度和回滚
- 租户、用户、角色与审计管理
- 监控、告警、备份、恢复和生产发布

### 6.2 P1：首发稳定后建设

- 更复杂的多 Agent 协作策略
- 精细化产品推荐和用户意图分析
- 人工客服工作台增强
- APP/H5 图片上传、截图问答和合同局部图片解读
- 运营质量报表和问题聚类
- 模型路由评分和成本优化
- Kubernetes 多实例、高可用和弹性扩缩容

### 6.3 P2：条件具备后评估

- Ollama/vLLM 私有化模型服务
- 量化和 LoRA Adapter 加载
- 领域模型适配实验
- ASR 语音输入和 TTS 语音播报
- gVisor 等更强沙箱隔离方案

## 7. 知识、动态数据与模型边界

### 7.1 Multimodal Knowledge Base

用于保存和检索：

- 贷款产品说明和申请条件
- 金融政策、合规制度和客服规范
- 合同模板及条款解释材料
- 常见问题、业务流程和材料清单

P0 支持：

- 原生 PDF
- 扫描 PDF
- PNG/JPEG 图片
- OCR 文本提取
- 版面与阅读顺序恢复
- 表格结构和关键字段提取
- 页码、区域坐标和原文件定位

P1 支持 APP/H5 用户上传截图或合同局部图片进行问答。P2 预留 ASR/TTS，不实现视频理解、实时视频客服或图片生成。

回答必须保存文档版本、chunk、检索分数和引用关系。

### 7.2 MCP/业务接口

用于获取：

- 实时产品和利率
- 用户额度或征信信息
- 贷款申请与审批状态
- 个性化还款计划
- 需要身份校验或明确授权的业务操作

没有合法授权时使用 Mock MCP 和模拟数据。

### 7.3 模型边界

模型不得：

- 编造利率、额度、征信、审批状态和合同义务。
- 将回答描述为正式授信、审批或贷款承诺。
- 在缺少证据时给出确定性的金融政策结论。
- 绕过 Skill Registry、MCP 授权、租户校验或安全沙箱。
- 直接信任文件扩展名、远程图片地址或未经安全检查的 OCR/文档内容。
- 未经确认直接执行具有业务副作用的高风险操作。

## 8. Agent、Skill 与编排范围

### 8.1 首批 Agent

- KnowledgeAgent：金融知识问答。
- ProductAgent：产品检索与推荐。
- ContractAgent：合同条款解读。
- ComplianceAgent：回答合规检查。

### 8.2 首批 Skill

- 金融知识检索
- 产品检索
- 利率查询
- 额度与审批查询
- 还款试算
- 合同解读
- 合规检查
- 转人工
- OCR
- 文档解析
- 版面分析
- 表格提取
- 图片问答
- 多模态检索

### 8.3 编排要求

- 支持顺序、并行、条件、DAG 和人工审批节点。
- 支持最大步数、截止时间、Token/费用预算和并发限制。
- 支持 Checkpoint、中断恢复、失败重试和确定性回放。
- Skill 必须具备 Manifest、Schema、版本、权限、依赖、启停、灰度和回滚。

## 9. 发布阶段

### 9.1 R1：H5 业务闭环

完成 H5 → Agent → RAG/Mock MCP → LLM → SSE 回复 → 引用/审计的最小闭环，并支持扫描 PDF/图片的安全解析、OCR、结构提取和可定位引用。

### 9.2 R2：APP/H5 双渠道候选版本

完成 APP 接入、图片上传与截图问答、运营端、人工转接、租户权限、Skill 管理、沙箱、可观测性和完整质量门禁。

### 9.3 GA：生产发布版本

在目标服务器环境完成五项核心目标的功能、安全、恢复、性能和容量验证，具备 HTTPS、密钥管理、备份恢复、CI/CD、监控告警和回滚能力。

## 10. 非目标

当前产品范围明确不包括：

- 自动授信、自动审批或具有法律效力的金融决策。
- 未经授权的真实征信、银行或资金方生产接口。
- APP/H5 之外的客户渠道。
- 无边界、无预算、无法回放的自主 Agent。
- 绕过 Skill Registry 的临时工具或脚本。
- 未经沙箱隔离的不可信代码与高风险本地任务。
- 首发阶段立即采用 Kubernetes、vLLM 或大规模模型微调。
- 视频理解、实时视频客服和图片生成。
- 首发阶段的语音输入与语音播报；只保留 ASR/TTS 扩展契约。

## 11. 产品成功定义

系统必须同时满足：

1. APP/H5 核心业务场景端到端验收通过。
2. 金融回答可追溯，动态数据只来自授权工具。
3. Agent、Skill、Memory、Multimodal Knowledge Base 和工具调用全链路可审计。
4. 扫描文档、图片和表格能够安全解析，并提供页级/区域级可追溯引用。
5. 跨租户泄漏和严重金融幻觉均为 0。
6. 五项核心技术目标全部达到 `non-functional-requirements.md` 的发布指标。
7. 生产环境完成部署、备份恢复、回滚、告警和故障处置演练。

## 12. 外部条件与待确认事项

以下内容不阻塞第 1 步，但必须在对应设计或接入前确认：

- 目标服务器的 CPU、内存、磁盘、网络和 GPU 配置。
- 生产域名、DNS、证书和网络访问策略。
- 首发模型供应商和计费限制。
- APP 登录态、用户身份和接口接入方式。
- 合法授权的金融知识与业务数据来源。
- 真实征信、银行和资金方接口的授权方式。
- 现有人工客服系统或待建设的客服工作台边界。
- 数据保存期限、删除流程和具体合规要求。
- 生产允许的文件类型、大小、页数、图片分辨率和保存期限。
- 用于 OCR、版面、表格和图片问答验收的代表性金融文档数据集。

如果目标服务器无法达到既定非功能指标，需要扩容、拆分或调整部署拓扑，不能通过删除核心指标完成发布。
