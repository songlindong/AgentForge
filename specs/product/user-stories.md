# AgentForge 用户故事

状态：第 1 步产品规格基线，待确认  
版本：0.1.0  
更新日期：2026-07-25

## 1. 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 正式生产发布前必须完成 |
| P1 | 首发稳定后建设，不阻塞首发 |
| P2 | 条件具备后评估 |

本文件记录产品层用户故事和验收摘要。具体 OpenAPI、状态机和 Given/When/Then 场景在后续模块规格中定义。

## 2. 贷款咨询用户

### US-CUS-001：H5 咨询（P0）

作为贷款咨询用户，我希望通过 H5 发起咨询并获得流式回答，以便快速查看产品、政策和合同信息。

验收摘要：

- 消息进入统一会话并具有 message_id、conversation_id 和 trace_id。
- 回答通过 SSE 返回，断开后取消下游请求。
- 回答展示来源、风险提示和最终状态。

### US-CUS-002：APP 咨询（P0）

作为 APP 用户，我希望使用与 H5 一致的客服能力，以便在登录态下继续已有会话。

验收摘要：

- APP 使用统一渠道契约接入，不复制后端业务逻辑。
- 用户身份和会话映射正确，不能访问其他用户或租户会话。
- APP 与 H5 在相同输入和业务状态下执行相同的 Agent/Skill 规则。

### US-CUS-003：带引用的金融知识回答（P0）

作为贷款咨询用户，我希望产品、政策和合同回答带有来源，以便核对原始资料。

验收摘要：

- 每个关键事实可追溯到有效文档版本和具体片段。
- 无有效来源时拒答、说明不确定性或转人工。
- 不混用其他租户、过期或无权限文档。

### US-CUS-004：动态数据查询（P0）

作为经过授权的用户，我希望查询利率、额度和审批状态，以便了解当前业务信息。

验收摘要：

- 动态值只来自授权 MCP/业务接口。
- 调用前完成身份、租户、权限和用途校验。
- 工具失败时不得由模型补全或猜测结果。

### US-CUS-005：还款计划试算（P0）

作为贷款咨询用户，我希望按照金额、期限和合法利率计算还款计划，以便比较产品方案。

验收摘要：

- 利率来源明确，计算过程可复核。
- 缺少必要参数时先询问用户，不自行补充关键数据。
- 结果明确标识为试算，不构成正式合同或审批结果。

### US-CUS-006：多轮会话（P0）

作为贷款咨询用户，我希望系统保留必要上下文，以便不重复输入产品、金额和期限。

验收摘要：

- 上下文不能串用户或串租户。
- 记忆具有来源、保存期限，并支持删除和过期。
- 超过上下文预算时使用可审计摘要。

### US-CUS-007：拒答与转人工（P0）

作为贷款咨询用户，我希望系统在无法可靠回答时明确说明并转人工，以避免获得错误金融信息。

验收摘要：

- 高风险、低置信度、资料冲突、工具失败或用户要求时可以转人工。
- 人工客服只获得处理当前会话所需的最小上下文。
- AI 停止自动回复后，人工接管状态对用户可见。

## 3. 人工客服

### US-CSR-001：接管会话（P0）

作为人工客服，我希望查看转人工原因、会话摘要、引用和工具状态，以便继续处理用户问题。

验收摘要：

- 展示的信息经过权限校验和脱敏。
- 接管、回复、转回 AI 和关闭会话均记录审计事件。
- 接管后 Agent 不得继续自动产生回复，除非人工明确恢复。

### US-CSR-002：纠正回答（P1）

作为人工客服，我希望标记错误回答和正确资料，以便进入知识纠错流程。

验收摘要：

- 反馈关联问题、回答、引用、模型、Agent、Skill 和 trace_id。
- 未经审核的反馈不能直接修改生产知识。

## 4. 知识运营人员

### US-KNO-001：文档入库（P0）

作为知识运营人员，我希望上传产品、政策、合同和 FAQ，以便建立金融 Knowledge Base。

验收摘要：

- 校验文件类型、租户、权限和敏感内容。
- 解析、切片、Embedding、BM25 和向量入库状态可追踪。
- 重复事件幂等，失败任务可安全重试。

### US-KNO-002：审核、发布和回滚（P0）

作为知识运营人员，我希望审核知识版本并进行发布或回滚，以便控制生产回答依据。

验收摘要：

- 草稿、审核、已发布、已停用和已归档状态转换受控。
- 发布和回滚保留操作人、时间、版本和原因。
- 已回滚版本不能继续用于新检索。

### US-KNO-003：质量评测（P0）

作为知识运营人员，我希望运行固定问题集并比较指标，以便阻止检索质量退化。

验收摘要：

- 使用版本化黄金集计算 Recall、Precision、MRR、NDCG、引用正确率和回答有据性。
- 指标低于发布门禁时阻止知识版本上线。

## 5. Agent 与 Skill 运营人员

### US-SKL-001：注册 Skill（P0）

作为 Agent/Skill 运营人员，我希望通过 Manifest 注册 Skill，以便 Agent 能够安全发现和调用标准能力。

验收摘要：

- Manifest 包含名称、版本、输入输出 Schema、权限、依赖、实现类型、超时和重试策略。
- Schema、依赖和权限校验不通过时不能启用。
- Skill 必须声明租户可见性和执行边界。

### US-SKL-002：Skill 版本、灰度与回滚（P0）

作为 Agent/Skill 运营人员，我希望对 Skill 进行版本发布、灰度和回滚，以便降低能力升级风险。

验收摘要：

- 支持指定租户、Agent 或流量范围灰度。
- 版本不兼容、被禁用或已回滚时不得继续调度。
- 发布前运行契约、权限、组合和回归测试。

### US-AGT-001：配置 Agent（P0）

作为 Agent/Skill 运营人员，我希望配置 Agent 的角色、模型策略、Memory、Skills、权限和预算，以便形成受控业务 Agent。

验收摘要：

- Agent 只能绑定有权限且版本兼容的 Skill。
- 最大步数、截止时间、Token/费用预算和人工审批点必须明确。
- 发布、停用和回滚均保留审计记录。

### US-AGT-002：编排 Agent 与 Skill（P0）

作为 Agent/Skill 运营人员，我希望使用顺序、并行、条件、DAG 和人工审批节点编排任务，以便实现复杂金融客服流程。

验收摘要：

- 编排定义可版本化、校验、回放和回滚。
- 节点失败、超时、重试和补偿行为明确。
- 禁止无限循环和越权调用。

## 6. 合规与审计人员

### US-COM-001：回答审计（P0）

作为合规人员，我希望查看回答使用的文档、模型、Agent、Skill 和工具，以便判断回答是否有据且合规。

验收摘要：

- 可通过 trace_id 关联完整执行链路。
- 审计内容经过权限控制，敏感字段脱敏。
- 审计事件防止未授权修改。

### US-COM-002：高风险操作审查（P0）

作为合规人员，我希望高风险工具和沙箱任务需要确认，以便阻止越权或不可逆操作。

验收摘要：

- 权限、确认、执行和结果形成完整审计链。
- 拒绝或超时后任务不能继续执行。

### US-COM-003：隔离与泄漏检查（P0）

作为合规人员，我希望验证租户之间没有数据泄漏，以满足数据隔离要求。

验收摘要：

- 覆盖 MySQL、Redis、Kafka、Milvus、OpenSearch、MinIO、Memory、Skill、缓存、日志和 Trace。
- 跨租户泄漏数量必须为 0。

## 7. 租户与平台管理员

### US-ADM-001：租户与角色管理（P0）

作为租户管理员，我希望管理本租户用户、角色和权限，以便实施最小授权。

验收摘要：

- 租户管理员不能修改其他租户。
- 权限变更立即或在规定时间内生效，并记录审计。

### US-ADM-002：模型与配额管理（P0）

作为平台管理员，我希望管理模型、路由、QPS、并发和 Token 配额，以便控制稳定性和费用。

验收摘要：

- 配额在多网关实例间保持一致和原子性。
- 超额请求得到明确错误，不拖垮下游模型。

## 8. 系统运维人员

### US-OPS-001：监控和故障定位（P0）

作为运维人员，我希望从渠道到 Agent/Skill、RAG、模型、工具和沙箱查看完整指标与 Trace，以便快速定位故障。

验收摘要：

- 核心链路具备日志、指标、Trace 和告警。
- 通过 message_id 或 trace_id 可以定位完整调用链。

### US-OPS-002：发布与回滚（P0）

作为运维人员，我希望通过受控流水线发布和回滚，以便降低生产变更风险。

验收摘要：

- 发布前执行规格、测试、RAG、安全和性能门禁。
- 异常版本能在规定时间内回滚。

### US-OPS-003：备份和恢复（P0）

作为运维人员，我希望备份并恢复关键数据，以便应对误操作、磁盘故障和版本问题。

验收摘要：

- MySQL、MinIO 和关键配置具备版本化备份。
- 按计划执行恢复演练并记录 RPO/RTO。

### US-OPS-004：容量管理（P0）

作为运维人员，我希望了解 Gateway 和 RAG 的容量上限，以便在达到风险阈值前扩容。

验收摘要：

- 完成并发阶梯和 100 万向量测试。
- 对并发、队列、延迟、错误率、CPU、内存、磁盘和网络设置告警。

## 9. 外部业务系统

### US-EXT-001：受控业务接口接入（P0）

作为外部业务系统，我希望通过明确契约、鉴权和幂等机制提供动态数据，以便安全接入 AI 客服。

验收摘要：

- 接口具有身份、租户、用途、超时、重试、幂等和审计约束。
- 测试环境可以使用 Mock MCP 完整替代。
